### 🔥 **8. Раздел 15: ADR (Architectural Decision Log)**

**ADR-15.1: Почему SQLite?**
```
Вопрос: Почему не PostgreSQL?
Решение: SQLite
Обоснование:
  - Простота (нет сервера)
  - Портативность (один файл)
  - Достаточная производительность
  - Соответствие ограничениям
```

**ADR-15.2: Почему raw_log_data?**
```
Вопрос: Зачем хранить сырые строки?
Решение: Таблица raw_log_data
Обоснование:
  + Аудит и доказательная база
  + Возможность переобработки
  - Увеличение размера БД (приемлемо)
```

**ADR-15.3: Почему employees ≠ positions?**
```
Вопрос: Почему отдельная таблица?
Решение: Нормализация
Обоснование:
  - Массовые обновления (один UPDATE)
  - Снижение ошибок
  - Логическая целостность
```

**Это классический ADR-формат из enterprise-практик!**
