# Time_work_table — учёт времени и расчёт зарплаты

Консольная система: импорт отметок терминала (DAT) → проверка и ручные правки →
расчёт часов и зарплаты → Excel-ведомость + персональные HTML + консольные отчёты.
Тесты проверены на Python 3.12.3, Windows; целевая версия указана в `.python-version`.

## Установка

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt        # runtime: openpyxl, rich
pip install -r requirements-dev.txt   # тесты и сборка: pytest, pyinstaller
```

TOML читается штатным `tomllib` (Python ≥ 3.11) — отдельный `tomli` не нужен.

## Быстрый старт

```powershell
# Без -k: меню в терминале — [1] учёт без зарплаты, [2] зарплата
# (ключ вводится скрыто через getpass: не виден и не попадает в историю shell),
# [0] выход. Вне терминала (CI/pipe) без -k — режим без зарплаты без вопросов.
py main.py -f 1_attlog.dat -y 2026 -m 7 --no-edit

# Расчёт июля 2026 в режиме учёта времени (без зарплаты: оклад = 0, молоко считается)
py main.py -f 1_attlog.dat -y 2026 -m 7 -k t --no-edit

# Тот же месяц с зарплатой (ключ — только цифры, длина 3–122)
py main.py -f 1_attlog.dat -y 2026 -m 7 -k <ключ>

# Интерактивные правки одиночных отметок и пропусков (без --no-edit)
py main.py -f 1_attlog.dat -y 2026 -m 7 -k <ключ>

# Восстановить несохранённую сессию правок
py main.py --resume -k <ключ>

# Включить сотрудников без единой отметки (отпуск/прогул весь месяц)
py main.py -f 1_attlog.dat -y 2026 -m 7 -k <ключ> --include-empty

# Свои каталоги: входные данные и результаты (дефолты: data/ и result/)
py main.py -f 1_attlog.dat -y 2026 -m 7 -k <ключ> --data-dir data --output-dir result
```

Год/месяц без `-y/-m` запрашиваются через `input`. Все пути относительные:
запускайте из корня репозитория. DAT-файл и справочники ищутся в `--data-dir`
(дефолт `data/`); `--pay-dir` без значения — `<data-dir>/pay_directory.db`.
Фактические каталоги показываются на стартовом экране.

## Режимы оплаты

| Ключ `-k` | Режим |
|---|---|
| нет флага + терминал | Меню: учёт без зарплаты / зарплата со скрытым вводом ключа / выход |
| нет флага + не терминал | Учёт без зарплаты, без вопросов |
| `t` / `0` | Учёт времени без зарплаты: ставки нулевые, молоко 40 ₽/день считается; наличие SQLite-базы оплаты этот режим не меняет |
| цифры (3–122 знака) | Расчёт зарплаты; неверный ключ — предупреждение + режим без зарплаты |

В режиме учёта времени файл ставок и база оплаты не читаются. В режиме зарплаты
модель выбирается так:

- **Новая модель** (общая база), если в `--pay-dir` (по умолчанию
  `data/pay_directory.db`) есть действующие общие условия на 1-е число месяца.
  Переход — с **2026-01**; периоды раньше всегда считает legacy-режим.
- **Legacy-режим** — в остальных случаях (нет файла/условий).
- Ошибка настройки новой модели — фатальна, без fallback в legacy.
  Версии/назначения действуют только с 1-го числа; mid-month — отказ до расчёта.

Управление справочниками новой модели:

```powershell
py -m core.pay_cli init                                # схема + стартовые условия
py -m core.pay_cli migrate                             # перенос сотрудников/ролей/исключений из .dat
py -m core.pay_cli show --date 2026-10-01              # действующие условия на дату
py -m core.pay_cli template --out template.toml        # пустой TOML-шаблон
py -m core.pay_cli export --out pay.toml               # экспорт справочника
py -m core.pay_cli import pay.toml --dry-run           # предпросмотр импорта
py -m core.pay_cli rules-history 1                     # история версий правил роли
```

## Входные данные

- **DAT-строка:** `ID YYYY-MM-DD HH:MM:SS ...` (хвост игнорируется).
  Невозможные даты (`2026-02-30`) пропускаются с диагностикой и номером строки,
  а не роняют импорт. За день на сотрудника берутся минимум (приход) и максимум
  (уход) отметок.
- **Справочники** (`data/variable_data_for_app/`): `id_employee.dat`
  (`id [role] фамилия имя`), `roles_employee.dat` (`[id] название`),
  `wage_rates.dat` (шифрованные ставки legacy), `settlement_exceptions.dat`
  (ID вне начислений), календарь `holidays.dat` / `postponed_working_days.dat`:
  `ДД.ММ` (наследие, год подставляется) или `ГГГГ-ММ-ДД` (только свой год);
  невозможные даты (`31.02`) отклоняются, пересечение праздника и переноса
  диагностируется. Дубли ID и неизвестные роли — ошибка до расчёта.
- **Дневные статусы:** `work` (будни), `weekend`, `holiday`, `vacation`
  (Отпуск), `truancy` (Прогул).

## Роли и правила (решение 2026-09-12; норматив — `documentation/spec_payroll.md`)

| Роль | Учёт | Норма | Одиночные | Ведомость | Бонусы |
|---|---|---|---|---|---|
| 0 Руководитель | — | — | не проверяются | нет (отдельный список в дашборде) | нет |
| 1 Работник цеха | факт, 2 метки | 8 ч | проверяются | да | переработка 1.5, полный месяц, стаж |
| 2 Кладовщик | факт, 2 метки | 8 ч | проверяются | да | нет |
| 3 Проживающий | 1 метка = выход | фикс 8 ч | не проверяются | да | нет |
| 4 Ремонтники | 1 метка = выход | — | не проверяются | **отдельный текстовый список дней, без начислений** | нет |

> Роль 4 — отдельный текстовый список выходов `Ремонтники_MM_ГГГГ.txt`, без начислений.
> Стажевая шкала пока не задана: бонус стажа 0 с предупреждением.
> Выходные/праздники в переработку не входят (их отдельная схема — открытый вопрос);
> молоко 40 руб. x выходы — допущение кода; отпуск/удержания — открытые вопросы spec §9.

Деньги legacy: ставка — **руб/смена 8 ч**; будни `ставка×дни + 1.5×(ставка/8)×переработка − (ставка/8)×недоработка`;
выходные `1.5×(ставка/8)×факт`; отпуск `ставка×дни`; кладовщик без оплаты
переработок, выходные по одинарной; роль 3 `ставка×(будни+выходные)` без молока.
Молоко — 40.00 ₽ × (будни + выходные выходы). Округление — `Decimal`, `HALF_UP`,
квантуется только итог.

Новая модель: база 60 000 ₽ / `D` рабочих дней / 8 ч; переработка месячная
`max(0, факт − норма)`; полный месяц строгий (все `D` дней, без отпуска/прогула,
факт ≥ нормы, без незакрытых отметок, занятость весь месяц, бонус 5 000 ₽);
основа стажа `M + переработка + полный месяц`.

## Сессии правок

Правки во время интерактивного редактирования атомарно пишутся в
`temporary.json` (JSON, не pickle) вместе с журналом правок — журнал
переживает `--resume` (запись журнала — до сохранения отметок; некорректный
журнал отклоняется до отчётов). Старые `.pickle` не загружаются.
Сессия хранит контекст запуска (справочник, модель, участники, календарь);
`--resume` продолжает тот же расчёт (тот же `--pay-dir`/календарь) или
предметно сообщает, почему это невозможно.
Без `--resume` найденная сессия бэкапится в `temporary_YYYY_MM.json`
и игнорируется; с `--resume` — восстанавливается после строгой валидации.
Если сессия для `--resume` не найдена, запуск завершается с понятной ошибкой.
Снимок запуска сохраняется и до генерации отчётов, поэтому повторное
завершение возможно даже без правок.

## Выходные файлы (в `--output-dir`, дефолт `result/`)

- `{МесяцRU}_{ГГГГ}.xlsx` — детализация + итоги (+ блок новой модели при bundle);
  месячные длительности — формат `[h]:mm:ss` (30 ч не оборачиваются в 06:00:00)
- `{Фамилия}_{id}_{MM}_{ГГГГ}.html` — персональный отчёт
- `payroll_versions_{ГГГГ}_{MM}.json` — версии условий/календаря новой модели (при bundle)
- `temporary.json` (+ бэкапы `temporary_ГГГГ_MM.json`) — сессия правок
- `Ремонтники_{MM}_{ГГГГ}.txt` — выходы роли 4 (без начислений)
- `payroll_{ГГГГ}_{MM}_rev{NN}.json` — завершённый пакет расчёта: ревизии
  не перезаписываются (связь `prev_package_id`), внутри период, алгоритм,
  точные версии условий/правил/назначений/шкалы, календарь по датам, отметки
  после правок, журнал, входы и компоненты итогов, участники и причины
  исключения, контрольные суммы источников и отчётов. Временная сессия
  удаляется только после записи пакета; Excel/HTML — файлы последнего запуска
  (привязка к ревизии — по sha256 в пакете)
- Консоль: старт-экран, дашборд, превью, зарплатная ведомость, журнал правок

Сессия из корня (от старых запусков) при старте разово переносится
в `--output-dir` с сообщением. В корень больше ничего не пишется.

## Сборка EXE

```powershell
.\generation_exe.ps1
.\generation_exe.ps1 -IncludePersonalData -DataFile '1_attlog.dat'  # opt-in
```

Скрипт останавливается на первой ошибке, идемпотентен (чистит `Time_table/`,
`Time_table.zip`, `build/`, `dist/`, `*.spec`). По умолчанию в дистрибутив
идут только неперсональные файлы (`holidays.dat`, `postponed_working_days.dat`,
`roles_employee.dat`, `README.md`); справочники сотрудников, ставки и DAT
доложите вручную (список печатается). С `-IncludePersonalData` они копируются
явно — проверяйте получателей архива.

В репозитории сейчас отслеживаются рабочие данные (журналы `data/*.dat`,
`company.db`/`line.db`/`line_new.db`, `company_data_real.toml`, ставки
`wage_rates.dat`, справочник `id_employee.dat`). Это кандидаты на вынос из git
(схемы + обезличенные примеры — в репозиторий, рабочие данные — отдельно
с правами и бэкапом). Удаление уже отслеживаемых файлов и чистка истории —
только по решению владельца: простое правило `.gitignore` историю не чистит.
Игнорируются: `*.xlsx`, `*.html`, сессии (`temporary.json`, `temporary_*.json`,
`*.pickle`), `_secret_key.tmp`, `payroll_versions_*.json`,
`payroll_*_rev*.json`,
`data/pay_directory.db`, `Time_table/`, `dist/`, `build/`.

## Ограничения

- Ночных смен и нескольких интервалов за день нет: день схлопывается в
  минимум/максимум календарной даты.
- Смена базы/роли/назначения/шкалы — только с 1-го числа (окончание назначения — конец месяца); внутри месяца — отказ до расчёта. Стаж — полные календарные годы до 1-го числа.
- `D = 0` (пустой календарь) — явная диагностика вместо деления на ноль.
- Неизвестная роль/нет назначения — понятная ошибка до правок и отчётов.
- Ключ в командной строке попадает в историю shell: предпочитайте меню
  без `-k` (скрытый ввод через getpass). Ключ `-k` хранится только в памяти
  запуска и на диск не пишется (F18): старый `_secret_key.tmp`, если остался
  от прежней версии, однократно мигрирует в память и удаляется — новые
  запуски файл не создают; преобразование ключа — обратимое, не шифрование.
  Переполнение при ключ×ставка (крайне длинный ключ) даёт `ConfigError`
  в момент расчёта ставок, а не крах.
- Год/месяц проверяются (1900–2100, 1–12; явный `0` — ошибка, а не запрос
  ввода); неверный ввод завершается диагностикой без трассировки.
  Справочники `id_employee.dat`/`roles_employee.dat`/`wage_rates.dat` разбираются
  по любым пробелам (несколько пробелов/табуляция допустимы), ошибки —
  с файлом, строкой и полем. Календарь принимает `ДД.ММ` (наследие) и
  `ГГГГ-ММ-ДД` (свой год), обе формы проверяются календарём.
- HTML-отчёты — валидный HTML5 (`doctype`, `lang="ru"`, `meta charset`),
  без вложенных `<tr>`; длительности везде `HH:MM:SS` (`str_timedelta`),
  деньги — `format_money` (`HALF_UP`, 2 знака), основания бонусов
  и причины исключения — дословно из расчёта/справочника.

## Структура и проверки

- `main.py` — последовательность импорта, правок, расчёта и отчётов; поддерживает
  `main(argv)` для запуска из другого Python-кода.
- `core/cli.py` — аргументы, проверка периода, меню и скрытый ввод ключа.
- `core/pay_context.py` — единый контекст периода (режим new/legacy, объединённый
  штат, действующие правила) до анализа и правок.
- `core/pay_package.py` — завершённый пакет расчёта с ревизиями (`payroll_*_rev*.json`).
- `core/payroll_service.py` — выбор режима оплаты для внешних вызовов (не используется
  основным сценарием `main.py`, у которого состав/диагностика богаче).
- `core/calculations.py`, `core/pay_calc.py` — legacy-формулы и новая модель.
- `core/config.py`, `core/session.py` — загрузка справочников (ключ — только в
  памяти, F18) и контексты восстановления состояния между запусками.
- `core/file_parser.py` — DAT и календарь; ключ кэша календаря включает
  абсолютный путь справочника и год.
