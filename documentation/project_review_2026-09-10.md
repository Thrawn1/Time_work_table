## Подтверждённые проблемы

### 1. P1 — новый расчёт удаляет проигнорированную сессию

**Код:** [main.py:76–79](../main.py#L76-L79), [main.py:167](../main.py#L167), [core/session.py:114–120](../core/session.py#L114-L120).

Без `--resume` программа сообщает, что найденная сессия будет проигнорирована. Однако после успешного расчёта безусловно вызывает `remove_session()`, удаляющий и JSON, и старый pickle.

**Сценарий:** есть сохранённый июнь; запускаем июль с `--no-edit`. После успешного расчёта июньские исправления удаляются. В изолированной проверке успешного нового запуска подтверждён вызов `remove_session()` несмотря на сообщение об игнорировании сессии.

При интерактивных правках старый JSON может быть перезаписан ещё раньше: сохранение всегда использует общий путь `temporary.json`.

**Исправление:** связать сессию с конкретным расчётом и удалять только использованный им файл. Для другого периода сохранять отдельную сессию.

### 2. P1 — исключённые сотрудники попадают в консольную зарплатную ведомость

**Код:** [main.py:140–163](../main.py#L140-L163), [core/ui.py:222–244](../core/ui.py#L222-L244).

`SETTLEMENT_EXCEPTIONS` учитывается при редактировании, создании HTML и заполнении Excel. Однако расчёт получает всю таблицу, а `build_preview_rows()` выводит всех сотрудников из `summary` без фильтра исключений.

**Воспроизведение:** у синтетических сотрудников 101 и 102 есть полные смены; ID 102 включён в исключения. В финальную консольную ведомость передаются оба ID с начислениями, но в Excel присутствует только сотрудник 101.

**Исправление:** один раз определить участников расчёта и использовать одинаковый состав для вычислений, предпросмотра и всех отчётов.

### 3. P2 — восстановление сессии допускает некорректные расчётные данные

**Код:** [core/session.py:86–106](../core/session.py#L86-L106), [core/analysis.py:54–57](../core/analysis.py#L54-L57).

Загрузчик проверяет возможность преобразования дат, но не проверяет порядок отметок, допустимость статуса и согласованность периода. Повреждённые записи молча отбрасываются.

Подтверждены сценарии:

- Приход `09:00`, уход `08:00` загружаются и не обнаруживаются поиском одиночных отметок. При условной ставке 800 за восьмичасовую смену начисление составляет **−100 без молока**, молоко — 40, итог — **−60**.
- Статус `wrok` вместо `work` принимается, восьмичасовой день даёт нулевое начисление.
- Повреждённая запись сотрудника исчезает из восстановленных данных без диагностики.
- `"entries": []` вызывает необработанный `AttributeError` вместо диагностируемого отказа в восстановлении.

Эти сценарии относятся к повреждённой или вручную изменённой сессии; корректный ручной редактор уже проверяет порядок вводимых отметок.

**Исправление:** валидировать схему и смысл данных целиком до восстановления; выдавать список ошибок вместо молчаливого частичного расчёта.

### 4. P2 — `--include-empty` не работает для полностью пустого месяца

**Код:** [main.py:84–93](../main.py#L84-L93).

Если за выбранный месяц нет исходных отметок вообще, программа завершает работу до обработки `--include-empty` и входа в редактор.

**Воспроизведение:** импорт возвращает пустой список, передан `--include-empty`. Программа завершается с кодом 1, редактор не вызывается.

**Последствие:** невозможно через этот флаг заполнить отпуск или прогул, если весь месяц отсутствовали все участвующие сотрудники.

**Исправление:** различать отсутствие входного файла и отсутствие отметок за период. При явно указанном периоде и `--include-empty` разрешать начать с пустой таблицы.

### 5. P2 — одна невозможная дата останавливает весь импорт

**Код:** [core/file_parser.py:11–17](../core/file_parser.py#L11-L17), [core/file_parser.py:29–35](../core/file_parser.py#L29-L35).

Строка подходящего формата с датой `2026-02-30` вызывает необработанный `ValueError`. Проверка месяца выполняется уже после разбора даты.

**Воспроизведение:** ошибочная февральская строка останавливает импорт **июльских** данных из общего файла.

**Исправление:** собирать ошибки импорта с номерами строк и причинами; затем явно решать, можно ли продолжить расчёт.

### 6. P2 — отчёты однофамильцев с одинаковыми именами перезаписываются

**Код:** [core/html_builder.py:18–21](../core/html_builder.py#L18-L21), [core/html_builder.py:91–92](../core/html_builder.py#L91-L92).

Имя HTML-файла содержит только ФИО и период. Два разных ID с одинаковыми ФИО получают один путь, второй отчёт заменяет первый.

**Воспроизведение:** генерация для двух синтетических сотрудников с одинаковыми именами дважды передаёт один и тот же путь в функцию записи HTML. Штатная функция открывает файл в режиме `w`.

**Исправление:** включить ID сотрудника в имя файла и нормализовать недопустимые символы.

### 7. P2 — внешние текстовые поля интерпретируются как разметка и формулы

**Код:** [core/html_builder.py:117–126](../core/html_builder.py#L117-L126), [core/html_builder.py:133](../core/html_builder.py#L133), [core/excel_builder.py:59](../core/excel_builder.py#L59).

Подтверждено на синтетических значениях:

- `<b>Changed</b>` в имени становится настоящим HTML-тегом в сформированной строке разметки.
- Имя `=1+1` записывается в Excel как формула — тип ячейки `f`.

Проверка HTML выполнялась на уровне генератора строк, XLSX — на уровне ячеек openpyxl. Исполнение формул в Excel и полный путь создания HTML с таким именем на Windows не проверялись.

**Исправление:** экранировать динамический текст через `html.escape`, а текстовые поля XLSX записывать явно как строки.

### 8. P2 — заданный автофильтр Excel ограничен строками 1–24

**Код:** [core/excel_builder.py:18](../core/excel_builder.py#L18).

В коде жёстко задан диапазон:

```python
ws.auto_filter.ref = 'A1:G24'
```

**Уточнение по вопросу о строках и столбцах:**

| Часть адреса | Значение |
| --- | --- |
| `A:G` | 7 столбцов: от A до G включительно |
| `1:24` | 24 строки: от 1 до 24 включительно |
| Строка 1 | Заголовки таблицы |
| Строки 2–24 | 23 строки данных внутри автофильтра |
| Строка 25 и далее | Находятся вне заданного диапазона автофильтра |

Таким образом, речь именно о **23 строках данных**, а не о 23 столбцах. Одна строка детализации соответствует записи сотрудника за дату, поэтому это также не ограничение в 23 сотрудника или 23 календарных дня.

**Данные не обрезаются при сохранении:** все сформированные строки остаются в книге. Ограничен именно диапазон, к которому привязан автофильтр.

**Воспроизведение:** сформирована книга в памяти с 31 строкой детализации. Последняя запись находится в строке 32, а `ws.auto_filter.ref` остаётся равным `A1:G24`. Следовательно, строки 25–32, то есть последние восемь записей, не входят в заданный автофильтр.

**Последствие:** при применении этого автофильтра по сотруднику строки вне его диапазона не участвуют в отборе и могут оставаться видимыми. Значение диапазона подтверждено программно; ручная проверка поведения интерфейса Excel не выполнялась.

**Исправление:** определять последнюю строку при записи детализации и задавать `A1:G{last_detail_row}`. Границу следует брать по детализации, а не по концу блока месячных итогов.

## Проблемы в тестах

### Проверки восстановления не вызывают приложение

**Код:** [tests/test_p1_bugs.py:367–424](../tests/test_p1_bugs.py#L367-L424).

Два теста восстановления настраивают подмены и аргументы командной строки, но не вызывают `main()` и заканчиваются `assert True`. Они не защищают сценарии сессий.

**Исправление:** действительно вызывать `main()` с изолированными зависимостями и проверять чтение источника, восстановление, сохранение и удаление сессии.

### Изменение рабочего каталога делает тесты зависимыми от порядка

**Код:** например, [tests/test_session.py:18](../tests/test_session.py#L18); аналогичные вызовы есть в других тестах этого файла.

Тесты вызывают `os.chdir(tmp_path)` без восстановления исходного рабочего каталога. Календарные тесты при этом читают справочники по относительным путям.

**Воспроизведение:** запуск сначала `tests/test_session.py`, затем `tests/test_file_parser.py` даёт **5 failed, 16 passed**. Все пять ошибок — `FileNotFoundError` для `data/variable_data_for_app/holidays.dat`: поиск выполняется из временного каталога предыдущего теста.

**Исправление:** использовать `monkeypatch.chdir()`, автоматически восстанавливающий каталог, и изолированные календарные фикстуры.

### Часть проверок игнорирует результат функции

**Код:** [tests/test_calculations.py:30–40](../tests/test_calculations.py#L30-L40).

В тестах отрицательных длительностей вызывается `str_timedelta()`, но проверяется исходный `timedelta`, а не полученная строка. Поэтому неверный результат форматирования не приводит к падению теста.

**Исправление:** проверять возвращаемое строковое значение на заранее заданном ожидаемом результате.
